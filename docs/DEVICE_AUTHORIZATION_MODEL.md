# 设备授权会员模型评估

日期：2026-09-20。状态：已按此方向实施；此文保留决策背景。代码、发行前缀选择、旧客户端升级边界和验证结果见 [设备授权实施说明](DEVICE_LICENSES.md)。

## 结论

建议采用「账号购买设备名额 → 一次性授权 → 设备独立传输」。这与项目最近的免登录配对、独立设备凭据和自动选路一致。账号负责付款、名额分配和撤销；每台设备用自己的身份建立连接和传输。后台记录的是会员授权归属，不是文件或聊天记录的归属。

买的是可同时授权的设备名额，而不是可累计兑换的永久激活码。例如 6 个名额可授权 6 台设备；旧设备解除授权后，同一个名额可以用于新设备。购买端仅管理会员不占传输授权名额，需要会员传输权益时再授权本机。

## 产品边界

| 场景 | 建议行为 |
|---|---|
| 无账号、无授权 | 保留本地离线直传；公共信令服务提供免费额度 |
| 无账号、已授权 | 用设备身份获得会员信令权益，无需购买账号保持登录 |
| 账号登录 | 用于购买、管理名额、生成授权、查看授权设备及撤销；登录本身不自动获得设备会员权益 |
| 同一付款账号授权多台设备 | 每台设备独立；不自动共享历史、文件、存储密钥或传输权限 |
| 已配对的不同账号设备 | 正常互传，各自按设备授权判断权益 |
| 退出账号 | 已兑换的设备授权保留；退出登录与解除授权分开 |
| 会员到期 / 退款 / 撤销 | 按权益有效期停止新增会员服务；正常到期不强行打断已经建立的直传；本地文件与离线功能保留 |

设备配对表示允许互相传输，会员授权表示谁为服务付费，两个关系必须分开。付款账号只能管理授权与必要的设备信息，不能因此读取设备上的内容。

首次授权需要访问授权服务。只能主动访问外网的设备，可用出站 HTTPS 兑换与查询结果，不要求公网入站。完全离线的设备继续使用局域网功能，无需向服务器证明会员状态；离线软件许可证属于另一个需求，不用六位短码承担。

## 会员与盈利

建议将新售产品表达为「设备服务包」，按授权设备数分档，可增购名额；持续提供的在线服务优先采用订阅，已有买断权益保留原有承诺。定价需根据活跃授权设备、在线连接时长、支持成本及转化实验确定，本轮不凭空给出价格。

当前免费信令额度为每设备每分钟 600 条，轻量消息为 90 条。仅解除信令限制，对普通用户的购买吸引力可能不足，且更换设备身份可绕开单设备计数，不能把这一计数视为可靠的付费边界。

商业价值可以围绕稳定的跨网连接服务、长期使用、多设备名额和集中授权管理表达。所有套餐都应优先保证文件直传速度、文件完整性与可恢复性，不靠人为降速、破坏续传来制造升级需求。付费转化是否改善，需要后续实验验证。

「不限信令次数」指正常使用不扣商业配额；仍保留异常请求频率、连接数、报文大小和防攻击保护。信令只承载连接协商及轻量消息，TURN / 托管文件中转的实际带宽单独核算，不能暗示购买信令会员就获得无限中转流量。后续云存储也可通过设备授权映射到付款方的共享额度，但设备不需要持有付款方账号令牌。

已授权设备与免费设备可以互传，但免费端仍按自身权益使用服务，不因为接触会员设备获得全局无限权限。为保护传输稳定性，免费配额应在新会话建立时判断，为已经允许的会话预留必要的协商、取消和恢复消息预算；额度不足明确显示发生在哪一端，不能在 ICE 协商过程中随机卡住。

## 六位授权码

- 格式固定六位，大写字母加数字。建议字符集 `ABCDEFGHJKLMNPQRSTUVWXYZ23456789`，排除 `0/O/1/I`；输入自动转大写，接受粘贴，展示可分组为 `ABC 234`，存储不含空格。
- 使用安全随机数生成。32 个字符的六位组合共有 1,073,741,824 种；空间有限，唯一性和防猜测是两个独立问题，不能仅靠随机生成。
- 后端唯一索引保证全局不重复，碰撞后有界重试；已使用、过期和撤销的码保留不可重用的指纹记录。国内外若为独立集群，必须由同一发行服务保证全局唯一，否则只能声称各集群内唯一。
- 建议有效期 10 分钟，一次使用；设备会员有效期跟随购买权益，不能把码的 10 分钟与会员期限混淆。
- 码以服务端密钥保护的指纹存储，避免短码空间被数据库泄露后的离线穷举直接还原；不在日志、埋点、第三方资源或页面 URL 查询参数中暴露兑换凭证。
- 按设备、网络来源和全局流量共同控制尝试次数与签发量；单个 deviceId / IP 限流不足以对抗批量注册及分布式猜码。有效码数越多，撞中任意一个码的风险越高。
- 六位码只用于激活，后续请求使用设备自己的高强度凭据和短期会话令牌，不把六位码作为长期密码。

建议扫码使用同一授权记录关联的高强度一次性随机凭证；手输六位码后由购买端确认目标设备，再正式占用名额。这样保留便于输入的短码，又降低短码被猜中后会员名额被直接盗用的风险。二维码和短码在同一事务中失效，不可分别兑换两台设备。购买端确认页面只展示设备名称、平台和可核对的设备标识。

以上流程是会员许可兑换，不等同于 OAuth 账号登录。短码限时、限频、避开易混淆字符的设计借鉴 [RFC 8628 的短码安全讨论](https://www.rfc-editor.org/rfc/rfc8628.html#section-5.1) 与 [输入体验建议](https://www.rfc-editor.org/rfc/rfc8628.html#section-6.1)。

## 名额与生命周期

1. 生成授权码时短暂预留一个空闲名额，过期或主动撤销后释放；防止同时生成多个码超卖最后一个名额。
2. 兑换时锁定授权记录和对应名额，验证当前会员仍有效、凭证未使用、设备身份可信，再原子地写入授权关系。
3. 同一设备重试同一次兑换返回已有结果，不重复占位；两个设备同时兑换，只能成功一个。短码和二维码竞争遵守相同规则。
4. 同一设备最多存在一个当前授权归属。其他账号的码不能静默覆盖既有归属，须明确解除或执行受控转移。
5. 购买端支持设备备注、到期日、最后在线、解除授权与换机。换机频率作为独立可配置风控，正常丢失或重装不能永久浪费名额。
6. 浏览器按持久化的独立安装身份计一台，多标签页共用身份；不同浏览器配置、隐身窗口或清除站点数据可能成为新设备。不能延续当前「所有 Web 实例合计一台」的计费方式，也不能声称能可靠识别一台物理电脑。
7. 续费延续当前授权，无需重新输入码。正常到期保留归属记录；降档在生效前提示选择保留设备，未选择时采用公开、稳定的默认规则。退款及滥用封禁走对应权益状态，不删除设备本地内容。
8. 设备会话令牌续期与会员授权续期分开。会员判断来自服务端授权状态，不能仅信任一个长期 JWT 中的会员标记；授权变化要使权限缓存及时失效。

## 最小界面

购买端：「设备会员」显示 `已授权 2 / 6 台`，提供「授权本机」「生成授权码」和设备列表中的「解除授权」。登录退出不与这些按钮混合。

每台设备：「本机授权」显示「免费设备 / 已授权 / 已到期」，操作为「输入授权码」「扫码授权」。桌面端没有摄像头时保留输入与粘贴；设备只显示脱敏的授权来源，不拿到付款账号的敏感信息。

传输页面继续以目标设备、文件和进度为中心。授权状态在设置中可见，只有额度真正阻止新任务时提示升级，不把会员进度条常驻主流程。

## 现有代码的改造范围

| 当前实现 | 改造方向 |
|---|---|
| `DeviceCredential` 已提供独立设备 ID 与凭据 | 作为设备身份基础；迁移元数据到允许无账号的设备注册层 |
| `Device.user` 非空，登录时绑定/换绑用户 | 不把新许可直接写入旧账号设备表；增加独立授权关系，逐步分开登录会话、设备注册与付费归属 |
| `DeviceService` / `MembershipService` 按登录设备计数，Web 多条只计一个名额 | 改为授权名额计数；管理账号登录不再被传输设备数卡住 |
| `MessageController.deviceSend` 固定免费限额，账号 `/send` 使用另一条路径 | 统一按设备身份、授权和任务判断服务权益，堵住登录路径绕过设备授权的可能 |
| `DevicePairingService.canSignal` 允许同账号自动互通 | 新的付款归属不能触发此分支；互传仍依赖设备配对与接收策略 |
| `WukongimPublishService.publishToUser` 向账号设备扇出 | 新传输任务按目标设备投递，不能按付款账号广播 |
| 账号历史与待收邮箱并存 | 新传输历史与续传状态归设备/会话；旧账号历史明确兼容，不顺带开放给新授权设备 |
| 现有订单、订阅、支付回调 | 保留支付接入，成功支付调整名额与有效期；退款、到期、增购沿用同一权益源 |
| 限流目前保存在单个进程 | 多实例前增加共享配额/风控存储；授权码消费与名额唯一性始终由数据库事务保证 |

建议增加授权记录、名额和兑换记录，以及审计事件；把授权查询集中为一个服务，供信令、额度展示与会员管理使用。账号关系只在付费权限决策中解析，不进入文件字节传输路径。

## 实施与验收顺序

第一阶段：设备名额、授权码签发/兑换/撤销/过期、数据库唯一性和并发回归，接入现有支付权益。第二阶段：Web 与 Flutter 的本机授权入口、扫码和购买端管理；新传输统一设备身份。第三阶段：迁移已有付费用户，并验证旧客户端兼容、会员到期及换机；按阶段收敛旧账号广播、历史与登录设备限制。

必须通过：最后一个名额被并发生成；同码两端竞争；兑换结果丢失后的重试；二维码与短码竞争；过期、撤销、退款后不能激活；退出账号后已授权设备仍可用；未授权设备不能借账号接口绕过额度；同付款方不同设备不会自动收到对方文件；身份重装后换机；多标签页不重复占位；会员到期后本地文件与离线续传不受影响。

迁移保留既有付费承诺。当前多浏览器共占一个登录名额的规则与新的按安装计费规则存在差异，需要单独兼容安排，不能直接改计数后批量停用旧设备。
