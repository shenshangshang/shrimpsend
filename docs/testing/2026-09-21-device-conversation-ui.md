# 设备会话 UI：实现与闭环验证

日期：2026-09-21。基于用户选择的方案 2，更新现有 Web 与 Flutter 客户端。

## 已实现

- 主界面统一为设备列表、设备会话、文字与附件合一的发送框。
- 主界面移除账号归属、设备长标识、协议标签等日常不需要的信息；硬件图标、可读设备名和可传输状态保留。
- 文件和文字共用一次发送操作；按钮互锁避免重复提交；保留快捷键、中文输入法组合保护、拖放、粘贴和待发文件管理。
- Web 草稿按设备隔离，窄屏返回列表后恢复；会话打开后定位到最新消息。
- 设置中集中接收目录、授权、会员、主题等入口，免登录可以使用本机设置。移动 Web 的返回、登录后的退出入口保留。
- Flutter 会话菜单保留搜索、文件管理、重命名、清理会话及移除设备。
- 接收继续直接写入下载目录或自选目录，原文件不覆盖。
- 统一浅绿配色、字号、留白及组件圆角，桌面与窄屏适配。

## 测试中修复的问题

1. Web `zh_CN` 直接交给 Intl 导致打开中文历史崩溃，现转换为 BCP 47 标签。
2. 简化界面后，补回低频功能入口、会员登录后返回目标页、手机设置返回与退出。
3. Web 输入框在窄屏返回时被卸载，现将设备草稿提升到布局作用域。
4. 消息菜单悬浮遮住文本，现放在气泡外；虚拟列表首轮测量后再对齐底部。
5. Mac 初始化与网络重连并发启动导致空引用/旧监听残留，现用启动合并、生命周期版本及实例请求版本丢弃过期启动。
6. 原接收路径测试仍假设消息缓存子目录，已更新为用户要求的直接目标目录。
7. 分享临时文件删除后未清理显式临时根下的空目录，现只清理其受控 staging 子目录。

## 范围与限制

- 本次真实环境覆盖本机 HTTP 直传、WebRTC、免登录文本和中断续传；未配置外部 S3 / WebDAV 服务，也没有模拟公网 NAT、异地丢包或移动真机。
- Mac 已实际启动、真实接收及校验；Mac 输入和布局使用 Flutter 组件测试验证。没有通过操作系统自动化逐项点击原生窗口，也不把它描述为手工原生 UI 验收。
- 本轮没有进行真实会员扣款。既有授权测试包含免登录授权、等待确认、失效恢复及刷新竞争。
- 保留的非阻塞提示：Web 虚拟列表 React Compiler 跳过自动记忆化；Flutter 旧 API 的弃用提示及三个插件的 PrivacyInfo 构建提示。
