# 设备状态与日常交互细节优化

本轮范围：Web、Flutter 和本地 Docker 后端。设备独立于登录账号、会员归属和授权备注；鸿蒙不在本轮范围。

## 梳理与已修复项

| 细节 | 原问题 | 改进 |
| --- | --- | --- |
| 免登录设备状态 | 在线信息和局域网地址依赖账号设备表；未登录时资料不完整 | 独立设备资料与会话租约，通过设备凭据更新，只向已配对设备发送通知 |
| 快速在线判断 | 部分刷新等待十分钟，浏览器没有周期心跳 | 15 秒轻量心跳，状态变化实时推送，30 秒列表兜底，45 秒租约、5 秒过期检查 |
| 可传输状态 | 服务端离线会清掉已验证的本地连接 | 信令状态与实际 HTTP / 反向拉取可达性分开；云端断开仍可探测和使用局域网 |
| 自动检查闪动 | 后台探测反复覆盖已有状态 | 已验证在线状态保持；后台复查不反复显示检测中，手动检查仍提供反馈 |
| 多窗口 | 共用信令连接标识及历史 sessionStorage 会话标识 | 每个页面独立连接、独立有序心跳；至少一个有效会话则设备在线 |
| 旧请求与重连 | 晚到的在线请求、旧列表、历史通知可能覆盖新状态 | 心跳序号拒绝乱序请求，设备资料版本防止倒退，恢复页面/网络时立即检查 |
| 本机改名 | 只改本地偏好，广播和 HTTP 接收服务仍用旧名称 | 设置保存后同步本机、设备资料、局域网广播、接收服务；接收端更新工作线程资料，无需重启监听或传输 |
| 设备备注 | 配对时缓存的所有名称都当作备注，覆盖真实名称 | 单独保存显式备注；空备注恢复真实名称；收到新的配对信息不会覆盖备注 |
| 离线改名 | 保存后无法可靠补同步 | 先保存本地及待同步名称，连接恢复自动补交；Web 明确提示同步或待同步 |
| 输入体验 | 空名称、长度不一致、弹窗控制器过早销毁 | 去首尾空格，限制 80 字符，拒绝控制字符，支持回车保存和取消；弹窗管理自己的输入框生命周期 |
| Mac 后台接收 | 隐藏窗口会关闭在线状态 | 桌面后台继续心跳和接收；保留移动端受系统限制时的生命周期处理 |
| 免登录页面连续性 | LAN 启动调用旧账号接口，401 可能跳到登录页 | LAN 地址和设备状态改为设备凭据接口，账号退出与设备传输状态分开 |
| 无效配对 | Web 在配对请求成功前就写本地记录 | 成功配对后才记录设备，降低失败操作留下无效设备的概率 |

历史记录中没有单独的备注标记，因此旧名称作为未知设备的备用名称；只有新建的显式备注覆盖设备真实名称。设备标识、配对关系、接收目录和历史消息保持各自独立。

## 在线语义和默认时限

- 正常上线、最后一个窗口主动关闭、改名：服务端提交后约 250 毫秒合并发送通知，不对每次心跳广播。
- 异常断电或进程消失：最后一次心跳后约 45–50 秒确认离线，不用“信令在线”承诺文件一定可达。
- 真实通道检测：直接 HTTP 优先，保留反向拉取；探测并发受限，不为探测建立 WebRTC 文件传输会话。信令连接每 10 秒检查回应。
- 浏览器被系统冻结或手机后台被系统挂起后，无法保证继续接收；租约会过期，恢复可运行时立即续期。
- 在线状态是设备近期可用性的观测，不应作为传输是否成功的依据；文件仍以接收确认、续传状态和实际保存结果为准。

配置已提取到 `.env.production.example`、外置 `docker/production.yml`：`DEVICE_PRESENCE_LEASE_SECONDS=45`、`DEVICE_PRESENCE_SWEEP_MS=5000`。客户端每 15 秒续期，不建议将租约设为少于两次心跳间隔。

新增表 `device_profiles` 和 `device_live_sessions` 随现有 Hibernate schema update 创建。租约保存在数据库中，服务重启不会立即丢失所有设备状态；旧会话每日范围外清理。

## 验证记录

- 后端：138 项测试通过，包含无账号注册资料、多会话、乱序、名称校验、租约过期、并发首次上线和设备权限边界。
- Flutter：354 项测试通过，1 项已有跳过；包含旧列表竞争、离线名称补同步、备注清除和双 HTTP 工作线程原地改名。
- Web：18 项测试及类型检查通过，覆盖设备资料、备注、会话隔离、文件收取等。
- 本地 Docker：浏览器设置中修改名称显示“设备名称已同步”，测试后还原原名称。
- 本地实时通知首轮测量：上线 298 ms、改名 285 ms、最后窗口下线 300 ms、异常停止 45.17 s。
- 最终后端复测：上线 318 ms、改名 281 ms、主动下线 292 ms、异常停止 49.49 s（受 5 秒扫描相位影响）。
- 同一信令设备两个连接实测：共用连接标识时心跳回应存在丢失；独立连接标识时两个连接均完整收到 6/6 次回应。
- 两个真实浏览器页面并行运行 71 秒：两页均为在线，均无断开记录；正常 Mac 客户端保持可传输。
- Mac 真实集成测试通过：从设置弹窗改名 1.28 s 后配对端读到新名称；HTTP 接收服务和广播名称同步；导航元素和位置保持；隐藏窗口 17 秒后仍在续期。测试还原原名称。
- Web 会话备注保存后列表与标题一致，清空后恢复设备真实名称；同时修复清空备注后冷启动缓存名称残留的问题。
- 正常 Mac 客户端收到 Web 的指定回归文本；4 MiB 文件在 1 MiB 处中断后继续传输，最终 SHA-256 一致，保存到原自定义接收目录。

可重复运行的验证入口：`scripts/smoke-device-presence.mjs`、`scripts/smoke-native-lan.py`、`app/integration_test/device_details_test.dart`（输出目录可用 `DEVICE_QA_OUTPUT` 指定）。原始本地结果保存在忽略提交的 `.local/device-detail-*` 文件中。
