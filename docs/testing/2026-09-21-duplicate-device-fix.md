# Mac 上两个同名手机条目的排查与修复

## 原因与证据

两条 `Xiaomi 25113PN0EC` 的设备 ID 不同：旧测试安装为 `android_uuid_c5792291-d8a5-4ad1-9a33-644f8186961c_local`，现用安装为 `android_uuid_e9aec3ca-1bbf-42a1-a940-ed806f8789b0_local`。前面的 Android 真机测试安装被测试工具清理后，重新安装生成了新的设备身份，旧配对未清理。

Mac 本地保存的配对仅含现用安装，但服务器仍返回两个配对；两条记录的 LAN 地址同为 `http://192.168.0.104:9080`。直接查询该地址的 `/device-info` 返回现用安装的 ID。

另一个缺陷是在线探测仅请求 `/probe` 并检查 HTTP 200。旧身份的地址已被新安装复用，这种探测会把“地址可达”误认为“旧设备仍在线”，也可能触发对旧身份的自动配对同步。

## 处理

- 通过 Mac 客户端实际“移除设备”菜单和确认按钮，清理已确认废弃的旧测试配对；保留现用手机、文件和聊天数据。
- 已知设备的直接探测、诊断、自检和反向连通检查改用 `/device-info` 核对预期设备 ID。每次仍只需一个 HTTP 往返，不新增串行探测。
- 未知身份的手动发现仍可使用普通探测，再读取设备资料。
- 移除设备时使正在等待的旧列表快照失效，避免删除后的条目被较早发出的刷新响应恢复。
- 不按名称合并设备：两台真实的同型号或同名手机仍是各自独立的设备。

## 验证

- Mac 原生 UI 测试完成选中旧设备、打开设备菜单、移除、确认、刷新并选中现用手机；同名手机条目为 **1**。
- 清理后重新读取服务器配对列表，Android 条目只剩现用手机。
- 恢复普通 Mac 客户端并重启后再次核对，Android 配对仍为 1 条，运行日志没有再探测旧身份；结果见 `.local/device-cleanup-after-restart.json`。
- 对同一实际手机地址探测：现用 ID 通过，旧 ID 被拒绝。
- 18 项回归测试通过，覆盖旧快照不能恢复删除项、同名独立设备不合并、地址复用、缺少身份、无效响应、响应超时、现有设备详情与文本传输。
- 修改范围静态检查无 error / warning，仍有既有 info 提示。

原生验证入口为 `app/integration_test/stale_device_cleanup_test.dart`，必须显式传入需要清理的旧测试 ID；没有在产品代码中硬编码设备名称或测试 ID。结果保存在 `.local/device-cleanup-result.json`，运行日志为 `.local/device-cleanup-native.log`。

后续 Android 本地真机测试继续使用同签名保留数据安装与 `flutter run` 测试入口，避免自动卸载清除设备身份。确实需要创建全新安装时，应将它视为新设备，并在验证结束后清理新增的测试配对。
